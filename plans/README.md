## Dependency notes

- Plan 001 restores a trustworthy one-command verification gate. No money or
  authority-state change should land while that gate is red.
- Plan 002 defines the net financial effect and immutable correction ledger
  that both issuance paths must share.
- Plan 003 depends on Plan 002 so WSFEX signs exactly the final canonical note
  representation, not an interim payload.
- Plan 004 can run after Plan 001 and in parallel with Plans 002–003 once the
  baseline is committed.
- Plan 005 is the only plan allowed to make provider/homologation observations.
  It must not turn successful mocked tests into a production-compliance claim.

## Dogfood evidence captured

- `bun run typecheck` fails in `apps/api/src/agent-routes.test.ts` because the
  fake Reclaim gateway still emits the old proof/session shape and because the
  optional `subjectId` is forwarded as `undefined` under
  `exactOptionalPropertyTypes`.
- Targeted tests report 9 passing and 1 failing. The failing Path B test expects
  11 tools while the runtime exports 13, so the test aborts before exercising
  the journey.
- The running API correctly returns 401 without the agent bearer credential,
  exposes 22 financial read capabilities with it, creates a case, and returns
  HTTP 503 `RECLAIM_CONFIGURATION_REQUIRED` when a readiness session is
  requested without provider configuration.
- The runtime manifest advertises only readiness and invoice CAE purposes for
  `tax_ar_reclaim_start`, while its invocation parser also accepts adjustment
  proofs and `subjectId`.
- `bun run build` passes, demonstrating why build success alone is not the
  release gate; `bun run check` must pass.

## Findings considered and rejected

- Giving the tax agent the trusted user/accountant tokens: rejected because it
  would destroy the independent human-approval boundary.
- Treating Reclaim as an invoice issuer: rejected because Reclaim proves an ARCA
  fact but does not create a CAE.
- Retrying ambiguous WSFEX calls with a new request identifier: rejected because
  exact request/payload replay is an existing safety invariant.
- Marking stablecoin settlement as FX ingress: rejected because settlement,
  BCRA/FX evidence, tax declaration, and financing review must remain separate.
